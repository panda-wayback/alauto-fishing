# 进程内订阅总线

## 目标
为本仓库提供统一的进程内发布/订阅机制，让多生产者按主题推送事件、多消费者订阅接收。

## 需求
- 调用方能按主题订阅、退订与发布事件；同一回调重复订阅不叠加。
- 多个线程可以同时发布与订阅。
- 单个订阅者出错不影响总线和其它订阅者。
- 回调在发布者线程执行，耗时工作由订阅方自行排队。
- 总线不含任何业务主题；主题、谁发布、谁订阅由使用方规定（真机见 [真机自动拉鱼](../../autofish/README.md)）。

## 方案
- 落点：`src/common/pubsub`（[接口](../../../src/common/pubsub/interface.yaml)），通用总线。
- 取舍：最新快照与版本作废由使用方的域总线实现（真机为 `src/autofish/events`），通用总线只管推送，理由是这些语义依赖业务主题。
- 取舍：选自建类型化进程内事件总线，不选 `queue.Queue` 扇出、信号库、响应式库或消息中间件，理由是零额外依赖、语义清晰，适合桌面单进程多线程。

## 不做
- 跨进程、持久化、远程 Broker。
- 在通用总线里定义业务主题。
