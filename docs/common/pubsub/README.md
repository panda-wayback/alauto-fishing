# 进程内订阅总线（Pub/Sub）

## 目标

提供本仓库统一的**进程内**发布/订阅机制：多生产者按主题推送事件，多消费者订阅或拉取最新快照；线程安全、契约清晰、可复用。属通用库，不写业务主题。不做跨进程 / 网络中间件。

## 要实现的

### 选型（已选定）

| 方案 | 结论 |
|---|---|
| **类型化进程内 Event Bus（选定）** | 主题枚举 + 不可变事件 + 线程安全 `subscribe` / `unsubscribe` / `publish`；另提供最新快照拉取。零额外依赖，契约可读，适合桌面单进程多线程。 |
| 仅用 `queue.Queue` 扇出 | 多主题广播与「只要最新一帧」需自建；易散落。不作主方案。 |
| `blinker` / 同类信号库 | 可用，但多一依赖且类型/快照要自补；本仓规模不值得。 |
| RxPY / 响应式流 | 表达力强，学习与调试成本高；本仓过重。 |
| MQTT / Redis / 消息中间件 | 跨进程才需要；单机禁止引入。 |

行业对应关系：经典 **Observer（观察者）** + **事件总线**；高频主题采用 **latest-wins（只保留最新）**。

### 核心契约

- **主题（Topic）**：闭集；谁可发布 / 谁应订阅由使用方能力文档规定（真机串接见 `docs/autofish/pipeline/`）。
- **事件**：不可变载荷；带时间戳；需要作废语义的主题另带版本号（如 `roi_version`）。
- **发布**：按主题通知当前订阅列表；**单个订阅者异常不得拖垮总线或其他订阅者**。
- **订阅 / 退订**：可动态增删；同一回调重复订阅不叠加。
- **推拉结合**：推 `subscribe`；拉 `snapshot()`（由域总线提供聚合快照）。
- **线程**：多线程可发布；回调在发布者线程 → 重活须自行排队，禁止在回调里阻塞截屏等 IO。
- **高频主题**：Frame 等 latest-wins，避免积压。
- **版本与作废**：状态变更可作废派生数据；错版本事件丢弃。

### 参与方约束

- 生产者只发职责内主题；消费者只经订阅/快照取数。
- 编排入口组装生产者并对外暴露 `subscribe` / `snapshot`。

### 代码结构

| 路径 | 职责 |
|---|---|
| `src/common/` | 通用库根（无业务） |
| `src/common/pubsub/` | 进程内总线：订阅 / 退订 / 发布 |
| `src/common/pubsub/bus.py` | `EventBus` |
| `src/autofish/topics.py` | autofish 域主题与事件 |
| `src/autofish/bus.py` | autofish 域快照 / 版本作废；委托 `EventBus` |

依赖方向：`autofish` / `sim` / `algo` → `common`；`common` **禁止**依赖业务包。

### 失败与不做

- 失败：回调阻塞、未退订泄漏、无版本校验错配。
- 不做：跨进程、持久化、远程 Broker、在 `common/pubsub` 写业务主题。
