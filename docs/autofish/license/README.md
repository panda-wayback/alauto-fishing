# 密钥激活

## 目标
没有有效密钥不能进入调试壳；密钥携带可用天数，首次激活后从激活当天起算到期。

## 需求
- 启动顺序：先检查[打包过期自毁](../expire/README.md)，再检查授权；无有效授权时显示激活页，输入有效密钥后进入主窗；激活页可直接退出程序。
- 密钥只携带天数与防重放随机数，并经签名；到期日不写进密钥，由激活时起算。
- 首次激活某个密钥：激活日为当天，到期日为当天加天数，并记录到本机台账。
- 同一密钥再次输入时沿用首次的激活日与到期日，不重新起算，防止删软件重装刷天数。
- 授权与首次激活台账保存在与安装目录、仓库数据目录分离的用户状态目录，不会随删除 `.app`、exe 或仓库 `data/` 而消失。
- 本地日期达到或超过到期日即视为未授权，须用新密钥激活；不触发自毁。
- 密钥非法或损坏时提示错误，不写入任何记录。
- 主控页顶部按天、时、分、秒倒计时到授权到期日 0 点，见[调试壳界面](../shell/README.md)；展示不代替启动门禁。
- 发放方用生成工具输入天数得到密钥字符串；生成工具只在本机使用，不随用户安装包发布。
- 日后接入服务端时仍按激活日起算，本机台账可被服务端结果替换。

## 方案
- 落点：`src/common`，负责密钥验签、本机授权与台账读写、授权是否有效，接口见 [接口](../../../src/common/interface.yaml)。
- 落点：`packaging`，提供按天数生成密钥的命令行与图形工具，接口见 [接口](../../../packaging/interface.yaml)。
- 落点：`src/tools`，提供激活对话框与主控倒计时。
- 取舍：先做离线半套（客户端与生成工具共用签名密钥），接受密钥可能被逆向，换取无需服务端即可发放。
- 取舍：与打包过期分成两套检查，因为「有没有权用」与「这个包该不该自毁」是两件事。

## 不做
- 联网校验、账号、设备绑定、吊销列表。
- 用密钥替代打包自毁。
- 防止用户清除用户状态目录或修改系统日期。
