# 声音开钓与会话状态（First Click / Session）

## 目标

可选能力：用**开钓水声**自动点第一下，进入带鱼漂的界面后，再交给现有 **Pos 拉鱼**；也可关掉声音，由用户自己点第一下，程序只拉漂；也可全部关闭，纯手钓。

起鱼水声与开钓水声易混，**不能只靠音频**；必须用**开钓会话状态机**规定何时才听声、何时才点第一下、何时才允许 Pos 拉扯。

## 要实现的

### 两大块（可独立开关）

| 能力块 | 做什么 | 关了会怎样 |
|---|---|---|
| **A. 声音开钓** | 听开钓水声 → 自动点第一下 → 等到鱼漂出现 | 用户自己点第一下开钓；程序不听声、不点第一下 |
| **B. 自动拉漂** | 有有效 Pos 后，按策略按住/松开（现有 Decide + Act） | 出现鱼漂后也不自动拉，用户自己拉 |

组合用法（已确认）：

1. **A+B 全开**：听声 → 点第一下 → 出漂 → 自动拉 → 丢漂结束 → 再听下一轮。  
2. **只开 B**：用户自己点出鱼漂界面；监控到漂后自动拉；结束后等人再开下一杆。  
3. **全关（A 关 + B 关）**：不听声、不点第一下、不自动拉；人自己钓。有 ROI 时 Capture/Detect **仍持续跑**（只出画面与 Pos，不控鼠）。

约束：

- A 与 B **互不替代**：主控勾选分离；细项进分页面。界面见 [`docs/autofish/shell/`](../shell/)。  
- A **不改 ROI**、不订 `ActionIntent`；B 仍只订 Pos + 钓鱼态。  
- **控鼠互斥（已确认）**：A 开启时，开钓第一下（`FIRST_CLICK`：停顿 + 按住 + 松开）独占鼠标；**仅当会话进入 `FISHING` 后** B（Decide 出按住意图 + Act 落键）才可接管。`WAIT` / `FIRST_CLICK` / `WAIT_BOBBER` 下 Decide **不得**发按住意图，Act **不得**按意图落键并须松手。禁止两套逻辑同时抢键。  
- **无「监控开关」**：有 ROI 则一直截图识别；框选只改范围大小。见 [`docs/autofish/shell/`](../shell/)。

### 开钓会话状态机（A 开启时）

```text
WAIT ──水声命中──► FIRST_CLICK ──按住松开完成──► WAIT_BOBBER
  ▲                                                    │
  │                         有效 Pos（出漂）─────────────┘
  │                              ▼
  │                           FISHING  ← 此后彻底交给 Pos 拉扯（B）
  │                              │
  └──── 丢漂满 1s / 出错 / 关 A ──┘
       （回 WAIT 后 ≥3s 才再听声）
```

| 状态 | 含义 | 声音 | 第一下 | Pos 拉扯（B） |
|---|---|---|---|---|
| `WAIT` | 等待开钓水声 | **仅此态听**（且冷却已过） | 否 | 否 |
| `FIRST_CLICK` | **正在做开钓第一下**（含按下前停顿 + 按住 + 松开） | 忽略 | 是 | 否 |
| `WAIT_BOBBER` | 等鱼漂出现 | 忽略 | 否 | 否 |
| `FISHING` | 拉鱼中 | 忽略 | 否 | 是（若 B 开） |

`FIRST_CLICK` 字面即「第一下」整段，不是「点完之后」：

1. 水声在 `WAIT` 命中 → **立刻进入** `FIRST_CLICK`（此后不再听声）。  
2. 本态内：随机等 **等待区间**（缺省 0.3～1.5s）→ 按住 **长按区间**（缺省 0.7～1.5s）→ 松开 → 再随机等 **松开后区间**（缺省 0.2～0.8s，避免立刻交 B）→ 才离开本态。  
3. 松开后等待完成 → 进入 `WAIT_BOBBER`。  
4. 等待 / 长按 / 松开后 三区间均可在「更多」配置并持久化。

时间与转换（已确认）：

| 事件 | 行为 |
|---|---|
| 水声命中 | 立刻进 `FIRST_CLICK`；本态内按**等待区间**均匀随机后再按住（缺省 0.3～1.5s） |
| 第一下按住 | 按**长按区间**均匀随机后松开（缺省 0.7～1.5s） |
| 松开后停顿 | 按**松开后区间**均匀随机后再进 `WAIT_BOBBER`（缺省 0.2～0.8s；仍属 `FIRST_CLICK`，B 不接管） |
| `WAIT_BOBBER` | **3s** 内无有效 Pos → 回 `WAIT` |
| `FISHING` | **任意丢漂后满 1s**（持续无有效 Pos ≥1s）→ 回 `WAIT`（本轮结束） |
| 回 `WAIT` 后听声冷却 | **至少 3s** 内不听声（避免收杆/拉鱼尾声误触发再抛） |
| 任一出错 | 回 `WAIT`（控鼠失败、识别异常、关闭 A 等） |

安全规则：

- **只有 `WAIT` 且冷却已过** 才允许模板命中并进入 `FIRST_CLICK`。  
- 其它态一律忽略水声（含起鱼水声）。  
- A 关闭：不跑会话机；出漂后是否拉扯只看 B。

### 仅开 B 时（无声音会话）

- 不进入 `WAIT` 听声逻辑。  
- 用户自行点出鱼漂后：有有效 Pos 即按现有鱼漂/意图逻辑拉扯（B 开）。  
- 无漂足够久则停止拉扯（与现有安全态一致）；不自动再点第一下。

### 音频与模板（A 用）

- 设备：macOS 选 BlackHole 等虚拟输入；**Windows 用 soundcard 枚举 WASAPI 环回**，选带 Loopback /「录游戏声」的扬声器项（如正在用的 DELL），勿选麦克风。试听走本机扬声器/耳机。  
- **打包种子会话（已确认）**：仓库 `data/audio_sessions/` 打进包内 `seed/audio_sessions`；首次（或用户目录缺该会话时）拷到本机 `data_root/audio_sessions`，回测列表可用。用户新建会话仍只写本机 data。  
- **打包种子模板（已确认）**：仓库 `data/audio_template/*.npy` → 包内 `seed/audio_template`；用户库缺同名文件时只拷 `*.npy` 到 `data_root/audio_template`（不覆盖、不拷 `active.json`）。内置只读模板仍只走 `assets/audio/`。  
- **模板库（已确认）**：用户库 `data/audio_template/`（可增删改名）；内置库 `assets/audio/*.npy`（只读，应用内列表展示，不可删改）。选中=开钓与回测的当前模板。禁止用系统文件夹对话框选模板。原单一 `template.npy` 视为库中一项并迁移/兼容。**内置默认按平台**：Windows → `windows.npy`，macOS → `macos.npy`（缺则再试 `default.npy` / `splash_template.npy`）。
- 匹配（已确认）：模板为单声道 `float32` 波形 `.npy`（无内嵌采样率；与实时采集同采样率使用）。Mel 频谱图上滑动 NCC（图像式 `matchTemplate`）找短模板；**入 Mel 前按短时帧峰值的高分位（约 95%）归一化**（抗单峰杂音尖刺；干净水花仍接近原峰值归一；实时与回测同一套）。模板先按能量裁到主体。触发还需分数相对近期基线**突然抬升**（默认 ≥0.08）。**仅 WAIT 且冷却已过才更新抬升基线**；**每次进入听声基线归零**；静音时基线始终衰减。默认阈值 **0.70**；静音门限默认 **-80dB**（短时峰 RMS）。  
- **搜索窗（已确认）**：实时保持长缓冲（模板长 + **2.0s**）。每次匹配用轻量双窗——短窗（模板长 + **0.8s**）与长窗（模板长 + **2.0s**，即整段缓冲）各做一次 Mel-NCC 取窗内最大；**最终分数取两窗较高者**，再过阈值与抬升门。不为沿缓冲多起点滑扫（易抬高环境基线导致漏识别）。回测仍整段滑过（独立匹配器）。
- **开钓页实时波形（已确认）**：开始监听后展示最近约 **20s** 滚动波形（同回测波形条风格）；命中时标橙区（带宽≈模板时长）。便于对照回测观测。
- **长录音回测（已确认）**：在「回测」页起停长录音；会话落在固定目录 `data/audio_sessions/session_*`，应用内列表选择与删除（不打开系统文件夹）。波形上拖选；可「标注水花」（绿）；用当前库模板回测（**独立匹配器**，不与实时监听抢状态），命中橙色区间画在波形上（带宽≈模板时长，右端为命中时刻）；展示分数为区间**峰值** Mel 相似。近邻重复触发（命中时刻相差不足 0.5s）合并为一条并只留最高分。选区可「另存为」新模板入库。  
- **已取消**：系统文件夹选会话/模板；「我听到水花了」；能量自动「标记水花声」；纯起止秒点选作为主交互。  
- 命中与切态日志：相似度、阈值、等待/按住/松开后时长、状态名。  
- **会话事件载荷（已确认）**：进入 `FIRST_CLICK`（水声命中）时，总线事件除状态外携带结构化字段：相似分、等待秒、长按秒、松开后秒、阈值；主控据此写日志。其它切态仍只用短说明字符串（如 `a_on` / `bobber_timeout`）。禁止再用 `|` 拼接串当协议。

### 失败

- A 回 `WAIT` 不得拖垮 Capture/Detect。  
- B 关时，即使会话到 `FISHING` 也不控鼠。

## 解决步骤

1. 音频输入、缓冲、模板匹配、旧独立窗、内置模板（已完成；已迁入壳「声音」页）。  
2. 开钓会话状态机 + 切态日志（已完成）。  
3. 挂接第一下：命中 → 等待 → 长按 → 松开 → 松开后停顿 → `WAIT_BOBBER`；三区间可在壳「更多」配置并持久化（已完成）。
4. 挂接出漂 / 丢漂满 1s / 3s 超时；回 WAIT 后听声冷却 3s（已完成）。  
5. 与 B 衔接：A 开时仅会话 `FISHING` 才允许 Decide 发按住 + Act 落键；非 `FISHING` 强制松手（已完成）。
6. 壳 UI 主控两勾选（A/B）+ 分页面 → [`docs/autofish/shell/`](../shell/)（已完成）。  
7. 匹配：Mel 频谱图滑动 NCC + 阈值 + 分数抬升门控（已确认；实现跟本页「音频与模板」）。  
8. 长录音 + 波形拖选 + 整段回测 + 选区入库（曾在声音页）（已完成）。  
10. 开钓页实时波形（≤20s）+ 命中橙标；实时与回测基线更新一致（已完成）。
